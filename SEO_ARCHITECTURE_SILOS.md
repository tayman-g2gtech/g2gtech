## 1. Diagnostic & Vision Stratégique

### ⚠️ Problématique Actuelle : La SPA Monolithique
Actuellement, le site repose principalement sur une structure **Single-Page Application (SPA)** avec des ancres de navigation (`#services`, `#product`, `#about`).

* **Dilution sémantique :** Une seule URL (`/`) tente de ranker sur des intentions hétérogènes (Conseil ServiceNow, Stack MERN, Automatisation n8n, Logiciel SaaS ITSM).
* **Plafond d'indexation :** Impossibilité de positionner des pages profondes sur des mots-clés de longue traîne hautement transactionnels.
* **Perte de puissance géo-ciblée :** Faible ancrage sur les enjeux de souveraineté locale (CNDP, Loi 09-08, hébergement au Maroc).

### 🎯 Objectif Cible
Déployer une **architecture en cocons sémantiques / silos stricts** à 5 branches étanches pour :
1. Maximiser la transmission de PageRank thématique sans fuite.
2. Établir une autorité thématique forte (*Topical Authority*) sur l'ESM et le SaaS en Afrique du Nord / Europe.
3. Créer un tunnel de conversion organique fluide entre les prestations de services et le produit logiciel SaaS propriétaire.

## 4. Règles Strictes de Maillage Interne

| Règle | Principe d'Étanchéité | Application Concrète |
| :--- | :--- | :--- |
| **1. Intra-Silo Descendant** | Page Mère ➔ Sous-Pages | La page Pilier présente chaque thématique et pointe vers les 3 sous-pages avec des ancres descriptives. |
| **2. Intra-Silo Ascendant** | Sous-Page ➔ Page Mère | Chaque sous-page intègre un fil d'Ariane et un lien contextuel vers sa page Pilier. |
| **3. Intra-Silo Transverse** | Sous-Page ➔ Sous-Page Sœur | Liens uniquement entre pages du **même silo** (ex: *ServiceNow* lie vers *Gestion des SLA ITIL*). |
| **4. Inter-Silos Strict** | ❌ Interdiction de liens directs entre sous-pages de silos différents | Évite la fuite et la confusion thématique pour les robots d'indexation. |
| **5. Pont Service ➔ Produit** | Silo 2 (ESM) ➔ Silo 5 (Produit ITSM) | Callout dédié vers la page Pilier `/logiciel-itsm-maroc/` comme alternative souveraine et clé en main. |

## 5. Spécifications Techniques & Implémentation Full-Stack

### A. Composant SEO Dynamique & Balisage Canonique (`react-helmet-async`)

```tsx
import { Helmet } from "react-helmet-async";

interface SEOProps {
  title: string;
  description: string;
  canonicalPath: string;
  schemaData?: object;
}

export const SEOHead = ({ title, description, canonicalPath, schemaData }: SEOProps) => {
  const baseUrl = "https://g2gtech.ma";
  const fullUrl = `${baseUrl}${canonicalPath.startsWith("/") ? canonicalPath : `/${canonicalPath}`}`;

  return (
    <Helmet>
      {/* Balises Essentielles */}
      <title>{title} | G2GTech Maroc</title>
      <meta name="description" content={description} />
      <link rel="canonical" href={fullUrl} />

      {/* OpenGraph / Réseaux Sociaux */}
      <meta property="og:title" content={`${title} | G2GTech`} />
      <meta property="og:description" content={description} />
      <meta property="og:url" content={fullUrl} />
      <meta property="og:type" content="website" />
      <meta property="og:locale" content="fr_MA" />
      <meta property="og:site_name" content="G2GTech" />

      {/* Données Structurées JSON-LD */}
      {schemaData && (
        <script type="application/ld+json">
          {JSON.stringify(schemaData)}
        </script>
      )}
    </Helmet>
  );
};
```
